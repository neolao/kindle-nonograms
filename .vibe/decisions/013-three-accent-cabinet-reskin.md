# Site reskin adopts a three-accent color system, superseding the single-accent rule

**Context:** A free-form concept mockup ("Nonogram Arcade") explored a bolder visual identity — a light "printed guide" aesthetic with a bordered panel, a duotone-shadow marquee title, dashed section rules, cartridge-style cards, and three accent colors (amber, magenta, teal) — deliberately unconstrained by the site's design system. The product owner asked to bring that identity onto the real library and puzzle pages.

**Decision:** The real site adopts the mockup's three-accent palette (a fixed hex per color, each already checked for legible contrast on light backgrounds), replacing the single muted-blue accent used since the original visual design pass. Each accent gets one consistent functional role reused across both pages — one for navigating away, one for the primary in-puzzle action, one for "completed" (shared by the win message and the library's solved stamp, so the two visibly connect) — plus decorative-only cycling (library row stripes, the marquee dot row) that carries no meaning. The puzzle grid's own rendering (clue borders, cell/palette colors) is untouched by this reskin; the new accents apply only to surrounding chrome, so the grid stays the calmest, most legible element on the page. On the puzzle page, the grid keeps its own bordered frame directly below the chrome panel, borders touching with no gap (a "frame + screen" look) rather than sharing one padded container — padding on any ancestor of the grid would break its existing fit-to-viewport measurement.

**Reason:** The product owner explicitly chose fidelity to the mockup's visual identity over the site's original grayscale-first rationale, aware this project targets (among other Kindle models) a color e-ink device. Giving each accent one fixed role instead of arbitrary reuse keeps the new palette reading as a deliberate system rather than decoration for its own sake, and keeps the win-banner/solved-stamp connection meaningful. Keeping the grid itself unstyled by the new accents protects the app's actual job (solving the puzzle) from being visually outcompeted by its own chrome.

**Rejected alternatives:** One shared padded panel wrapping the whole puzzle page including the grid — rejected because it would need padding on an ancestor of the grid, which the grid's fit-to-viewport measurement cannot account for and would risk reintroducing a scrollbar (see `.vibe/decisions/011-chrome-padding-excludes-grid-wrapper.md`). Literal, non-functional mockup props (a coin-slot graphic, "insert coin" copy) — rejected as decoration that doesn't fit the real product's voice; only the mockup's structural/typographic/color system is carried over.
