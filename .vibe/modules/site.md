# Module: site
**Role:** Static-site generator — discovers/validates puzzle content, renders every page, and orchestrates the full build.
**Files:** `packages/site/src/discoverPuzzles.ts`, `packages/site/src/theme.ts`, `packages/site/src/sharedStyles.ts`, `packages/site/src/renderPuzzlePage.ts`, `packages/site/src/renderLibraryPage.ts`, `packages/site/src/htmlEscape.ts`, `packages/site/src/build.ts`, `packages/site/src/build-cli.ts`
**Exports:** `loadPuzzleSources(dir): Promise<Puzzle[]>`, `FONT_STACK`, `LABEL_FONT_STACK`, `COLORS`, `BORDER_WIDTH`, `SPACING_PX`, `MIN_TAP_TARGET_PX` (`theme.ts`) — plain TS constants: a conservative body-text font stack plus a second monospace `LABEL_FONT_STACK` layered on top for headings/buttons/badges/section labels only (never body copy, where it hurts legibility at Kindle's small sizes); a light paper/panel neutral pair; and the site's three-accent "cabinet" color system — `amber` for navigating away or an active toggle state, `magenta` for the primary in-puzzle action, `teal` for "completed" (shared by the win banner and the library's solved stamp so the two visibly connect), plus decorative-only cycling elsewhere (library row stripes, the marquee dot row) that carries no meaning; deliberately never applied to the puzzle grid's own rendering, so the grid stays the calmest, most legible element on the page (see `.vibe/decisions/013-three-accent-cabinet-reskin.md`); three border widths, a chrome spacing scale separate from the grid's own `em`-based sizing, and the minimum touch-target size — interpolated into literal CSS strings at build time rather than CSS custom properties, since `var()` support on Kindle's old WebKit is uncertain — same pattern as the palette-driven `.run-cN` classes below, `sharedStyles(): string` — the CSS fragment shared by both page renderers, built from `theme.ts`'s tokens: a subtly paper-textured page background, a duotone-shadow page heading, the decorative dot-row and rule-flanked section-label styles, the `.page-header` row (back-link + language switcher on the puzzle page), button styling (reused as-is by the back-link via a shared `button,.back-link` selector, now colored by accent role) including a visible `:focus` outline and a thicker amber border on `[aria-pressed="true"]`, the language-switcher layout, the `.play-toolbar` button-grouping layout, and the library page's bordered/shadowed `.panel` wrapper — every rule targets an individual chrome element rather than `body`, so the puzzle page's `.grid-wrapper` stays free of any added margin/padding (see `.vibe/decisions/011-chrome-padding-excludes-grid-wrapper.md`); the paper texture and panel box-shadow add zero layout footprint, so they can't affect that measurement either, `renderPuzzlePage(puzzle, assetVersion?): string`, `renderLibraryPage(puzzles: Puzzle[], assetVersion?): string` — visible markup shows only id/name/size per puzzle, but every puzzle's full data (including its solution) is also embedded as JSON so client hydration can check saved progress for a correct solve; the heading, empty-state message, and every solved badge each carry a `data-i18n` key so the client-side language switcher can retranslate them (the server-rendered text itself is always the English default, since there is no per-request rendering to know a visitor's locale ahead of time); `renderPuzzlePage` additionally renders a static `.page-header` row with a "Back to puzzle list" `<a href="../../" data-i18n="play.backToLibrary">` link — plain server-rendered markup, so it works even before hydration runs or with JS disabled — and gives `.grid-wrapper` its own bordered "screen" frame (`box-sizing:border-box` so the border can't push it past its JS-set `max-width`/`max-height` cap), a separate bordered element below the chrome rather than one shared padded container (padding there would break the grid-fit measurement); `renderLibraryPage` styles its `ul`/`li` list as bordered cards with a side stripe cycling through the three accents purely as decoration, its `.solved-badge` as a bordered, fixed-rotation stamp colored with the "completed" accent, and reserves a fixed-size `.thumb` placeholder (a neutral "?" glyph, never the puzzle's own solution) in every row for `hydrateLibraryPage.ts` to replace with a real preview once that puzzle is solved; the puzzle page's `.grid-wrapper` is `overflow:hidden` rather than a scrolling container — see `modules/client.md`'s `fitGrid`/`hydratePlayPage` note for why that only actually clips instead of silently growing the page, `escapeHtml(text): string`, `embedJson(value): string` — serializes a value for safe embedding in a `<script type="application/json">` tag, escaping `<` so an embedded `</script>` can't break out, `versionQuery(assetVersion?): string` — formats an optional asset version as a `?v=` suffix, `buildSite({ puzzlesDir, outDir }): Promise<void>` — discovers/validates puzzles first (fail-fast before writing anything), wipes and recreates `outDir` itself, builds the client bundle via Vite's programmatic API at a fixed `assets/main.js` path, then writes the home page and one page per puzzle, all referencing the bundle with the same content-hash-derived version query string
**Depends on:** `modules/shared.md`
