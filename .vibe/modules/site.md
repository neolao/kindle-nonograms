# Module: site
**Role:** Static-site generator — discovers/validates puzzle content, renders every page, and orchestrates the full build.
**Files:** `packages/site/src/discoverPuzzles.ts`, `packages/site/src/theme.ts`, `packages/site/src/sharedStyles.ts`, `packages/site/src/renderPuzzlePage.ts`, `packages/site/src/renderLibraryPage.ts`, `packages/site/src/htmlEscape.ts`, `packages/site/src/build.ts`, `packages/site/src/build-cli.ts`
**Exports:** `loadPuzzleSources(dir): Promise<Puzzle[]>`, `FONT_STACK`, `COLORS`, `BORDER_WIDTH`, `SPACING_PX`, `MIN_TAP_TARGET_PX` (`theme.ts`) — plain TS constants (a conservative font stack, a mostly-grayscale color set, three border widths, a chrome spacing scale separate from the grid's own `em`-based sizing, and the minimum touch-target size) interpolated into literal CSS strings at build time rather than CSS custom properties, since `var()` support on Kindle's old WebKit is uncertain — same pattern as the palette-driven `.run-cN` classes below, `sharedStyles(): string` — the CSS fragment (base typography, button styling including a visible `:focus` outline and a thicker border on `[aria-pressed="true"]`, and the language-switcher layout) shared by both page renderers, built from `theme.ts`'s tokens, `renderPuzzlePage(puzzle, assetVersion?): string`, `renderLibraryPage(puzzles: Puzzle[], assetVersion?): string` — visible markup shows only id/name/size per puzzle, but every puzzle's full data (including its solution) is also embedded as JSON so client hydration can check saved progress for a correct solve; the heading, empty-state message, and every solved badge each carry a `data-i18n` key so the client-side language switcher can retranslate them (the server-rendered text itself is always the English default, since there is no per-request rendering to know a visitor's locale ahead of time); the puzzle page's `.grid-wrapper` is `overflow:hidden` rather than a scrolling container — see `modules/client.md`'s `fitGrid`/`hydratePlayPage` note for why that only actually clips instead of silently growing the page, `escapeHtml(text): string`, `embedJson(value): string` — serializes a value for safe embedding in a `<script type="application/json">` tag, escaping `<` so an embedded `</script>` can't break out, `versionQuery(assetVersion?): string` — formats an optional asset version as a `?v=` suffix, `buildSite({ puzzlesDir, outDir }): Promise<void>` — discovers/validates puzzles first (fail-fast before writing anything), wipes and recreates `outDir` itself, builds the client bundle via Vite's programmatic API at a fixed `assets/main.js` path, then writes the home page and one page per puzzle, all referencing the bundle with the same content-hash-derived version query string
**Depends on:** `modules/shared.md`
