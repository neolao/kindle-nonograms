# Module: client
**Role:** Vanilla TypeScript frontend, built with Vite (es2015 target) for compatibility with Kindle's browser.
**Files:** `packages/client/src/main.ts`, `packages/client/src/progressStorage.ts`, `packages/client/src/contrastColor.ts`, `packages/client/src/i18n.ts`, `packages/client/src/hydratePlayPage.ts`, `packages/client/src/hydrateLibraryPage.ts`
**Exports:** `main.ts` has no exports of its own — it is the shared entry point bundled for every generated page, importing `hydratePlayPage.ts`/`hydrateLibraryPage.ts` purely for their self-invoking side effects (each self-detects its own page shape by a distinct marker and no-ops otherwise: `hydratePlayPage` by a `<table>`, `hydrateLibraryPage` by the embedded `#puzzles-data` script); `saveProgress(puzzleId, progress): void`, `loadProgress(puzzleId): PuzzleProgress | undefined` — persists a puzzle's progress to `localStorage`, degrading silently if storage is unavailable, throws, or holds corrupted JSON; `contrastingTextColor(backgroundHex): string` — picks black or white, whichever wins the WCAG contrast ratio against a given `#rrggbb` background, falling back to black for a malformed color instead of throwing; `readLocaleCookie(): string | undefined` / `writeLocaleCookie(locale): void` — persist the player's language choice to a `kindle-nonograms-locale` cookie, degrading silently if cookies are disabled or throw; `resolveLocale(cookieValue, navigatorLanguage): Locale` — pure function picking the effective locale (cookie, then browser language by primary subtag, then `DEFAULT_LOCALE`); `applyLocale(locale): void` — sets `document.lang` and retranslates every `[data-i18n]` element in place, no reload; `buildLanguageSwitcher(currentLocale, onChange): HTMLElement` — builds the FR/EN dropdown (a native `<select>`, deliberately not a custom control, for reliable behavior on Kindle's old WebKit) with a translated label, calling `onChange` on selection; `hydratePlayPage.hydrate(): void` — the interactive entry point for a generated puzzle page: inserts the language switcher right after the heading, resolves the locale, builds a Fill/Cross mode toggle, a "Check"/"Vérifier" button, and (once there is more than one palette color) a color swatch per entry, plus a win banner — all translated from the start and carrying `data-i18n` keys so a later language change retranslates them — restores saved progress onto the grid, and wires one delegated click listener that toggles a tapped cell's mark, redraws only that cell, saves progress, and shows/hides the win banner via `isPuzzleSolved`. The Check button unconditionally reveals the same banner on demand with whichever message currently applies ("Puzzle solved!"/"Not solved yet"); both this manual path and the automatic tap-triggered one route through a shared `setBannerMessage` helper that also swaps the banner's `data-i18n` key to match, so a later language change re-translates whichever message is actually showing rather than reverting to a stale one. The banner carries `aria-live="polite"` so its message is announced to assistive tech whenever it changes. A filled cell gets a solid `background-color` matching its palette color and nothing drawn on top — a plain square; a crossed cell explicitly clears both background and text, so no fill color ever survives a filled→crossed transition. The color swatch buttons are likewise plain solid-color squares; only the active one carries a `✓` checkmark in `contrastingTextColor`'s pick, as the non-color cue for which color is selected; `hydrateLibraryPage.hydrate(): void` — the entry point for the generated home page: inserts the language switcher right after the heading and applies the resolved locale (before checking whether the puzzle list is empty, so both the switcher and the translated empty-state message show up on an empty library too), reads every puzzle's full data embedded in the page, checks each one's saved progress with `isPuzzleSolved`, and reveals the matching row's `.solved-badge` node — a puzzle with no, incomplete, incorrect, or corrupted/wrong-shaped stored progress is treated as not solved rather than marked or crashing
