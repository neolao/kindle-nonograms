# Module: client
**Role:** Vanilla TypeScript frontend, built with Vite (es2015 target) for compatibility with Kindle's browser.
**Files:** `packages/client/src/main.ts`, `packages/client/src/progressStorage.ts`, `packages/client/src/contrastColor.ts`, `packages/client/src/i18n.ts`, `packages/client/src/fitGrid.ts`, `packages/client/src/hydratePlayPage.ts`, `packages/client/src/hydrateLibraryPage.ts`
**Exports:** `computeFitFontSizePx({naturalWidth, naturalHeight, availableWidth, availableHeight, baseFontSizePx, minScale, maxScale}): number` — pure function computing the single font-size (px) that scales an already `em`-sized grid to fit the available space: the smaller of the width/height fit ratios, a small safety margin, clamped to `[minScale, maxScale]` and rounded down (so a rounding error clips unused margin, never a real cell); falls back to the clamped base size when either the natural or the available size is zero/negative rather than dividing by zero; `main.ts` has no exports of its own — it is the shared entry point bundled for every generated page, importing `hydratePlayPage.ts`/`hydrateLibraryPage.ts` purely for their self-invoking side effects (each self-detects its own page shape by a distinct marker and no-ops otherwise: `hydratePlayPage` by a `<table>`, `hydrateLibraryPage` by the embedded `#puzzles-data` script); `saveProgress(puzzleId, progress): void`, `loadProgress(puzzleId): PuzzleProgress | undefined` — persists a puzzle's progress to `localStorage`, degrading silently if storage is unavailable, throws, or holds corrupted JSON; `contrastingTextColor(backgroundHex): string` — picks black or white, whichever wins the WCAG contrast ratio against a given `#rrggbb` background, falling back to black for a malformed color instead of throwing; `readLocaleCookie(): string | undefined` / `writeLocaleCookie(locale): void` — persist the player's language choice to a `kindle-nonograms-locale` cookie, degrading silently if cookies are disabled or throw; `resolveLocale(cookieValue, navigatorLanguage): Locale` — pure function picking the effective locale (cookie, then browser language by primary subtag, then `DEFAULT_LOCALE`); `applyLocale(locale): void` — sets `document.lang` and retranslates every `[data-i18n]` element in place, no reload; `buildLanguageSwitcher(currentLocale, onChange): HTMLElement` — builds the FR/EN dropdown (a native `<select>`, deliberately not a custom control, for reliable behavior on Kindle's old WebKit) with a translated label, calling `onChange` on selection; `hydratePlayPage.hydrate(): void` — the interactive entry point for a generated puzzle page: resolves the locale, then joins the language switcher into the static `.page-header` row (which already holds a server-rendered "Back to puzzle list" link) instead of inserting a new row right after the heading — an extra row there would shrink the space left for the grid-fit calculation below — falling back to the old insertion point when no such row exists, and calls `applyLocale` once so that static back-link's `data-i18n` markup is retranslated immediately on load. It then builds a Fill/Cross mode toggle, a "Check"/"Vérifier" button, and (once there is more than one palette color) a color swatch per entry, plus a win banner — all translated from the start and carrying `data-i18n` keys so a later language change retranslates them — restores saved progress onto the grid, and wires one delegated click listener that toggles a tapped cell's mark, redraws only that cell, saves progress, and shows/hides the win banner via `isPuzzleSolved`. The Check button unconditionally reveals the same banner on demand with whichever message currently applies ("Puzzle solved!"/"Not solved yet"); both this manual path and the automatic tap-triggered one route through a shared `setBannerMessage` helper that also swaps the banner's `data-i18n` key to match, so a later language change re-translates whichever message is actually showing rather than reverting to a stale one. The banner carries `aria-live="polite"` so its message is announced to assistive tech whenever it changes. A filled cell gets a solid `background-color` matching its palette color and nothing drawn on top — a plain square; a crossed cell explicitly clears both background and text, so no fill color ever survives a filled→crossed transition. The color swatch buttons are likewise plain solid-color squares; only the active one carries a `✓` checkmark in `contrastingTextColor`'s pick, as the non-color cue for which color is selected. `hydrate()` finishes by calling `computeFitFontSizePx` (via `fitGrid.ts`) to fit the grid to the available viewport space, applying the result as the grid wrapper's `font-size` — natural size is measured off the `<table>` itself rather than its wrapper `<div>`, since a `<div>` stretches to its container's width regardless of content while a `<table>` shrink-wraps to its own. It also sets the wrapper's `max-width`/`max-height` to the same measured available space: the wrapper's `overflow:hidden` (see `modules/site.md`) clips nothing on its own without a bounded box, so this pairing is what actually makes it a fail-safe rather than a no-op, even for a puzzle so large that the scale floor still isn't enough to make it fit. The fit re-runs on `resize` and whenever the win banner transitions from hidden to visible (the only banner change that can shrink the available space enough to matter); `hydrateLibraryPage.hydrate(): void` — the entry point for the generated home page: inserts the language switcher right after the heading and applies the resolved locale (before checking whether the puzzle list is empty, so both the switcher and the translated empty-state message show up on an empty library too), reads every puzzle's full data embedded in the page, checks each one's saved progress with `isPuzzleSolved`, and reveals the matching row's `.solved-badge` node — a puzzle with no, incomplete, incorrect, or corrupted/wrong-shaped stored progress is treated as not solved rather than marked or crashing
