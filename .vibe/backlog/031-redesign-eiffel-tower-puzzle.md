# Redesign the "Eiffel Tower" Puzzle to Be Fairly Solvable

## Description
The new solvability check added by [[023-puzzle-solvability-and-duplicate-validation]] found that the existing "Eiffel Tower" puzzle (previously `data/puzzles/71ab7bf0-0f03-4f91-823c-16269a90d83d.json`, 15×15, monochrome) is not fully derivable by line-based logical deduction alone — at least one cell (row 0, column 2 in the original grid) requires guessing. It was removed from `data/puzzles/` rather than shipped in a state the new build-time check would now reject, since redesigning its pixel art is a content decision, not something to make unilaterally while implementing the validation itself.

## Acceptance Criteria
- [ ] A new puzzle file (new id, since the old id is retired) recreates a recognizable Eiffel Tower silhouette, close to the original 15×15 monochrome design.
- [ ] The new grid passes both the solvability check and the duplicate check (it must not exactly match another puzzle's solution).
- [ ] The build (`npm run build`) and full test suite succeed with the new file in place.

A programmatic search for single-cell tweaks found 5 candidates that make it fully solvable (0-indexed row,col, all currently empty → filled): (10,7), (12,7), (14,6), (14,7), (14,8). Each closes a symmetric "gap" cell in the tower's legs/base, which would visibly affect the silhouette — a deliberate redesign (rather than an arbitrary single-pixel patch) is likely to give a better result. Once [[029-web-based-puzzle-editor]] exists, it could help iterate on a fair replacement design.
