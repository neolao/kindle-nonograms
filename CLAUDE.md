## Project overview

Kindle Nonograms is a nonogram (picross) puzzle game meant to be playable directly in the built-in browser of a Kindle e-reader. It is a full-stack application: a Node.js backend serves the game API and static assets, and a lightweight TypeScript frontend renders the puzzle grid, targeting the constraints of an old e-ink WebKit browser (no heavy animations, conservative JS baseline).

**Stack:** Node.js / TypeScript, npm workspaces monorepo, Express (server), Vite (client build), Vitest (tests), Biome (lint/format)
**Type:** Full-stack (Node.js API + browser frontend)

## Project language

English — all documentation, backlog items, code comments, and other generated content for this project must be written in English.

## Architecture

npm workspaces monorepo with three packages: `shared` holds domain types and pure logic used by both sides, `server` is the Express API (and will serve the built client in production), `client` is the vanilla TypeScript frontend built with Vite, targeting `es2015` for compatibility with Kindle's browser.

```
kindle-nonograms/
├── packages/
│   ├── shared/   # domain types and pure helpers shared by server and client
│   ├── server/   # Express API (src/app.ts builds the app, src/index.ts starts it)
│   └── client/   # vanilla TS frontend, built with Vite (es2015 target for Kindle's browser)
├── package.json  # workspace root — test/lint/build scripts
├── biome.json    # lint + format configuration
└── vitest.config.ts
```

### TDD workflow

For every feature or fix:

1. **Write tests first** — describe expected behavior through tests before writing implementation
2. **Confirm tests fail** — run `npm test` and verify new tests fail (red)
3. **Write implementation** — minimum code to make tests pass
4. **Confirm tests pass** — run `npm test` and verify all tests pass (green)
5. **Refactor if needed** — clean up while keeping tests green
6. **Run lint** — run `npm run lint` and fix any issues
7. **Present result** — summarize what was done, what was tested, and the test output

### Bug fix workflow

## Testing conventions

- Test location: colocated with source, `packages/*/src/**/*.test.ts`
- Test runner: Vitest — run all packages from the root with `npm test`
- One test file per source module
- Test names must describe behavior: `"returns empty list when input is empty"` not `"works"`
- Always cover: happy path + at least 2 edge cases + error/invalid input

## Kindle browser constraints

- Kindle's built-in browser is an old WebKit engine — no reliance on very recent JS/CSS features.
- The client build targets `es2015` (see `packages/client/vite.config.ts`) — keep this in mind when adding syntax or APIs.
- E-ink displays have slow refresh rates — avoid animations, transitions, and frequent re-renders; favor static, high-contrast layouts.

## Constraints

- Never leave dead code or unused imports
- Never hardcode secrets — use environment variables
- Never skip tests to meet a deadline — fix the code instead
- Style is enforced by tooling, not by convention — always run `npm run lint` before presenting results
